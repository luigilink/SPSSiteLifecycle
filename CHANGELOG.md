# Change log for SPSSiteLifecycle

The format is based on and uses the types of changes according to [Keep a Changelog](https://keepachangelog.com/en/1.0.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- Project skeleton: CI workflows (Pester on Windows and Linux, PSScriptAnalyzer, release,
  wiki sync), contribution files, issue and pull request templates, security policy and the
  first wiki pages.
- Common module `SPSSiteLifecycle.Common` and the settings file: a PowerShell data file read with
  a complete, strict check (unknown key, key in the wrong section, type, range, missing file,
  refused tenant), a schema that is the single source of truth, `Get-SPSLifecycleSetting` and an
  example file. The Microsoft corporate tenants are always refused.
- Tolerant CSV reading (separator detection, `sep=` line, UTF-8, UTF-16 and Windows-1252, empty
  rows, a file open in Excel), ISO 8601 dates that are never guessed from the culture, and the
  importers for lock date lists, exclusion lists and the SharePoint, Teams and Microsoft 365
  groups activity reports (matched by site ID when a report hides the site URLs).
- Verdict engine and catalog: gates checked in a fixed order, and a decision never lifts a
  safeguard. System sites are protected by template and by path, and the template table of
  Microsoft 365 Archive gates the archive. The Configuration and Verdicts wiki pages are
  generated by `tools/Update-Documentation.ps1`, and a test fails when they are out of date.
