# Change log for SPSSiteLifecycle

The format is based on and uses the types of changes according to [Keep a Changelog](https://keepachangelog.com/en/1.0.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Changed

- The lock date lists and the exclusion lists are read with a strict structure (#22), as the lock journal is: a quote
  that is never closed (it swallows the rows after it), a stray quote, a row that is cut short or has a value too many
  (they were dropped without a message) and a value under a column that has no name stop the tool and name the
  file and the line, because a row that is lost protects no site (exclusions) or leaves an older lock date in force (lock
  dates). The encoding stays the one that Excel writes (UTF-8, UTF-16, Windows-1252), except that a byte order mark is a
  declaration: an invalid byte after a UTF-8 mark, or a lone surrogate after a UTF-16 mark, stops the tool instead of
  becoming U+FFFD in a web address. What stays tolerant is the meaning of a row (a lock date row without a date is
  ignored, `SiteId` is optional, the empty rows that Excel adds are ignored), and the activity reports are read as before.
  A list whose rows were shorter than its header, which was read, now stops the tool. The messages of a lock date that
  cannot be read name the line, and so do the first values of an exclusion list that are not addresses.

### Fixed

- The tenant name and the names of the settings are read one character at a time (#24). `TenantName` accepted
  the Kelvin sign (U+212A) and a capital I with a dot above (U+0130), which a regular expression that ignores the case
  reads as a `k` and an `i`; the rule is now ASCII letters, digits and hyphens, matched as it is written, and a message
  that shows a name writes the characters that are not printable ASCII as `\uXXXX`. The entries of `RefusedTenants` follow the
  same rule, because an entry that can never be the name of a tenant refuses nothing. A setting whose name held a
  zero-width space or a soft hyphen (`Refused<zero-width space>Tenants`) was read as the setting that it looked like, then
  never found, so the list of refused tenants, or any other setting, was dropped without a message: the names are now
  compared with `OrdinalIgnoreCase`, and a name that is not known stops the tool and shows the hidden character. The check
  right before the sign-in repeats the rule on the tenant name, and wants an ASCII admin address.

### Added

- Project skeleton: CI workflows (Pester on Windows and Linux, PSScriptAnalyzer, release,
  wiki sync), contribution files, issue and pull request templates, security policy and the
  first wiki pages.
- Common module `SPSSiteLifecycle.Common` and the settings file: a PowerShell data file read with
  a complete, strict check (unknown key, key in the wrong section, type, range, missing file,
  refused tenant), a schema that is the single source of truth, `Get-SPSLifecycleSetting` and an
  example file. The Microsoft corporate tenants are always refused.
- Tolerant CSV reading (separator detection, `sep=` line, UTF-8, UTF-16 and Windows-1252, empty
  rows, spaces around the names of the columns, a file open in Excel), ISO 8601 dates that are
  never guessed from the culture, true and false values as a spreadsheet in another language
  writes them, and the importers for lock date lists, exclusion lists and the SharePoint, Teams
  and Microsoft 365 groups activity reports (matched by site ID when a report hides the site
  URLs). Every row of an exclusion list must be a site URL, because a row that cannot be read
  would protect nothing. Site URLs are compared in a canonical form (default port, percent-encoding,
  case and trailing slashes do not count).
- Verdict engine and catalog: gates checked in a fixed order, a decision never lifts a
  safeguard, and an input that is missing or cannot be read (a group state that was not read, a
  size that is blank or not a number) never leads to an action. System sites are protected by template and by path, and the template table of
  Microsoft 365 Archive gates the archive. The Configuration and Verdicts wiki pages are
  generated by `tools/Update-Documentation.ps1`, and a test fails when they are out of date.
- The Scan report writer: the CSV file that a person reviews in a spreadsheet and that the Act phase
  reads. UTF-8 with a byte order mark, the separator of the settings, sizes in whole megabytes, ISO 8601
  dates and a compact `GeneratedOn`, `Decision` always empty, no owners, a title neutralized against
  formula injection, and a file that is never overwritten. The columns are a table that the new Report
  wiki page is generated from (#3). The lines are written one at a time to a partial file that takes
  the name of the report only when it is complete, so that 260,000 sites need about 200 MB and a run
  that stops half-way leaves no report that looks complete. A text that starts or ends with a space
  is quoted, because an unquoted field loses its leading spaces when it is read.
- Paths: a relative path of a file or a folder is resolved against the location of the PowerShell session,
  and never against the working directory of the process, which `Set-Location` does not change (#19).
- Lock dates: the lock journal is read (a journal that does not exist yet is an empty one), and the lists
  and the journal are merged into one index in which the latest date wins and a site is found by its ID
  before its address: a renamed site keeps its date, a site that reuses an address does not inherit the
  date of the old one, and a site whose ID is unknown has no date. The journal is read strictly, unlike a
  list: a row without a date, with a bad site ID or with no site, and a quote that is never closed, stop
  the tool, because an ignored row could leave an older date in force. The journal goes through a strict
  CSV reader (RFC 4180 and nothing more): a stray quote, a quote that is never closed, a row too long
  or cut short and a value under a column with no name stop the tool and name the line of the file,
  where `ConvertFrom-Csv` would have lost the row. The reader never gives the whole file to a .NET
  method at every record, because on Windows PowerShell copies the arguments of every .NET method call
  into a log message (AMSI), which made the reading quadratic there (260,000 records are read in 5 s on
  a Windows runner; the first version needed hours), and the CI jobs now have a timeout. The journal must be UTF-8, with a byte order mark or
  not (a file that holds only ASCII, as French Excel saves it, is UTF-8 too), and a byte that is not valid
  UTF-8 is never replaced or guessed, after a byte order mark or without one: a character that is read
  wrong changes a web address, and the row would no longer match its site, so an older date of the site
  could win. A lock date before 2000-01-01 stops the tool, in a list and in the journal, because a
  spreadsheet writes a blank date as 1900-01-01, 1899-12-30 or 1970-01-01, and a site whose lock is read
  as a century old would look old enough to delete, and adding to the journal refuses such a date
  too, so that the tool never writes a journal that it cannot read. A row is added to the journal without damaging a
  file that Excel saved: its separator and columns are kept, the whole file is checked first, a file
  that is not UTF-8 or that does not follow the CSV rules is refused and left as it is, and the row is
  flushed to the disk (#4).
- Column names are compared one character at a time, whatever the culture: a header with a hidden
  character (a soft hyphen) is no longer the column that it looks like, and the message shows the
  character. A header that only looks like a column that the tool knows (`Site ID`, `Site_Id`, a hidden
  character, `Is Deleted` with a soft hyphen) stops the tool, because the column would be read as absent
  and its meaning lost without a message. An accent or a dot that is a separate character (a capital `I`
  and a combining dot above, which would compose into a dotted `I` that is a letter of its own) does not
  hide a lookalike either, and the message writes a combining mark as `\uXXXX`.
- The Scan core (`ConvertTo-SPSLifecycleScanRow`): a pure function that takes the records of the listing, the
  settings and the indexes, and gives one row per site with the columns of the report, so that the whole Scan
  logic is tested offline (#5). The rows go down the pipeline one at a time, straight to the report writer, and a
  summary counts the sites read, listed and left out, and the rows per verdict and per suggested action. A site is
  matched with the SharePoint report by its ID, and by its address only when a row has no site ID: the row of another
  site that had the address is never given to it, and the site is then in no report (`REVIEW-NO-ACTIVITY-ROW`). The
  Teams and groups reports are matched by the ID of the group, the latest date wins, and the report that gave it is
  named. OneDrive sites, and sites whose lock state the Scan does not ask for, are left out and counted. A record that
  has no address, no usable site ID or a content change that is not a date stops the Scan and names the record. The
  exclusion lists are merged into one index like the lock dates. A record whose group ID is neither empty nor a GUID,
  whose hub flag or channel flag is not True or False, or that has no template, stops the Scan too, because a
  safeguard would silently not apply. The OneDrive rule recognizes the host of OneDrive whatever its case and the user
  information in front of it. A site whose address is not in the form that SharePoint gives is left out with the
  OneDrive sites (`SKIP-ONEDRIVE`) because nothing can say what it is: an address that does not parse, a scheme other
  than https, a port other than the default one, the dot of the DNS root, or a host that the IDNA mapping changes (a
  soft hyphen, a full-width letter) or refuses (a bidirectional isolate, which first made the check fail with an
  error, and then hid the OneDrive host behind user information). A site left out by mistake is safe, and no list of
  spellings is complete when they are combined: the root site, the home site and the excluded sites are compared by
  their address as text, and an address with the dot of the DNS root or in http would not have matched. The system,
  channel and OneDrive templates are recognized whatever their case and the culture of the machine: under Turkish
  settings the `-like` operator did not read `FUNSITE#0` as `FunSite#*`, and a system site would have lost its
  protection by template. The core takes about 70 s for 259,000 sites instead of 250 s: the
  constant tables of the verdict engine are built once, and the lock date entries are hashtables, because the
  garbage collector took four fifths of the time. The tests run 5,000 and 20,000 sites and compare the times, so that
  a time that grows with the square of the size fails on any system.
- The listing of the tenant (`Get-SPSLifecycleTenantSite`), which the Scan reads the sites with (#6). It lists
  the sites page by page (about 1,500 a page) with the paged call of the SharePoint admin API, filtered on the
  server by the lock state when a single one is asked, and falls back on `Get-PnPTenantSite`, saying why, when
  the installed PnP.PowerShell does not have the types and members that the paged call needs. After each page
  it saves a checkpoint (a manifest, one file per page with its SHA-256, and a lock file), and an interrupted
  run takes it up where it stopped when it is for the same tenant, filter and way of asking, is less than 24
  hours old, has dates that can be true (a clock that was set back is seen), holds every page intact and has
  pages that form a chain of tokens (a page removed from the middle of the manifest is seen); otherwise it says
  why, in words and with a code that names nothing (`StartCode`), and starts again, and a listing that finished
  is never reused. The pages go down the pipeline one at a time. A page that fails is asked again, and a token
  that was already asked, a page with no token and a token that is not a text stop the listing. The OneDrive
  sites that came anyway and the addresses that SharePoint does not give are left out and counted. A site that
  comes twice is kept once when the two readings agree on the fields that a safeguard or a verdict reads, the size
  and the date of the last change included (compared by a 64-bit digest: 61 MB for 260,000 sites), and stops
  the listing when they do not. A property that the call did not
  load reads as `$null` in PowerShell and would have hidden a safeguard for every site, so every site is
  checked for it, not the first of each page, and a page with a property that is not loaded stops the listing.
  A size is a whole number of megabytes: a blank one is not known (the Scan gives it a review verdict), and a
  boolean, a fraction, a text or a value out of range stops the listing instead of reading as 0, 1 or 2.
  Everything that touches the tenant is in `Private/Adapters` (the check of PnP.PowerShell 3.0 or later, the
  sign-in, which checks the refused tenants and the address of the admin site again right before it, the
  sign-out and the read of a page), every call stops on an error (a cmdlet that gives some sites and then
  writes an error is not taken for a last page, and a sign-in that gives no connection stops the tool), and a
  test fails when a command that signs in, or a type of the admin API, is written anywhere else, or when a
  command is built at run time outside the adapters. The refused tenants are one rule that the settings and the
  sign-in share. The tests never reach a tenant: the commands of PnP.PowerShell are replaced by stubs that are
  checked before each test, throwing tripwires stand on the sign-in, and the tests that look at the real types
  load the libraries of types only, in a process of their own (and run only where PnP.PowerShell is
  installed). Without a tenant, the checkpoint takes 22 microseconds to write and 32 to read a record, a
  record is converted in 30, and 259,500 sites in 173 pages are listed in 12 s (11 s when the run resumes at the half). A lab script,
  `tools/lab/Test-TenantListing.ps1`, runs the listing against a tenant and only reads: it reports the pages,
  the times, counts and checks (a resume after a stop gives the same sites as a run that starts again, and the
  sites can be compared field by field with `Get-PnPTenantSite`), with no tenant name, address, account or title
  in what it prints and writes (what it shows comes from lists in the script: no text that the module or a library
  writes is passed on, by whatever stream it comes, and the text of an error is never shown: it goes to a file of
  the output folder; the versions are numbers, and a value that is typed wrong is named by its parameter and never
  given back), and its logic is tested offline. The call has not run against a tenant yet: the first run is the lab.
- Act: the reviewed Scan report is read and checked as a whole before any action (#10), by
  `Import-SPSLifecycleReviewedReport`. It reads `Url`, `SiteId`, `GeneratedOn` and `Decision`, with the strict structure and the
  tolerant encoding of the lists (Excel's semicolons, UTF-16 and Windows-1252 are read, a quote that is never closed or a row
  that is cut short stops the tool), and stops on the first problem in the order of the file, naming the line and the value:
  a missing column, an address that is not one of the tenant (another tenant, the admin site, a OneDrive address, http, a
  port, a host that DNS does not read as it is written) or that is one of a refused tenant, a site ID that is not a GUID (the
  zeros of a concealed report included), a site that appears twice by its canonical address or by its site ID (a row without a
  decision counts), a decision that is not `Delete`, `Archive` or `Lock` (a hidden character or a lookalike letter is not accepted;
  the case and the spaces are), and a `GeneratedOn` that cannot be read (the message names `CsvDateFormats`, for a date that Excel
  rewrote), that is in the future (5 minutes of margin for two clocks) or older than `MaxCsvAgeDays`. An empty list of decisions
  is not an error: it says that there is nothing to do. It gives the rows that have a decision with their line, the count of each
  action, and the date and the age of the file (the oldest of its rows), for the banner. It reads the file and nothing else.
- Scan: the home site of the tenant is read (`Get-PnPHomeSite`, one read after the sign-in) and protected. The verdict engine already
  protected the home site, but nothing gave it its address, so the Scan would have suggested it. A failure to read it, or an answer that is
  not the https address of a site, stops the listing before any page. The lab script reports whether the tenant has one.
- Scan: the entry script `src/SPSSiteLifecycle.ps1` runs the Scan phase (#7), with `-ConfigFile` and `-Phase` and no other parameter,
  through the new public function `Invoke-SPSLifecycleScan`. The settings, the activity reports, the lock date lists and the exclusion
  lists are read and checked before the sign-in window opens; the report is started before the sign-in too, so that a report that exists
  already stops the run. The Scan lists the sites, gives each its verdict, writes `sites-<time>.csv` in the output folder (a run that
  stops half-way leaves no report that looks complete, an interrupted listing is taken up the next time), and writes a summary as
  lines of information: the time, how the sites were listed, the sites in the report and the sites left out, the suggested actions,
  the verdicts by count, and the path of the report. The script exits with 0, or with 1 after a message that says what stopped it and
  that nothing was changed in the tenant. `-Phase Act` says that the phase is not available in this version, and exits with 1.
- Act: each row is read again from the tenant right before its action, and gets its verdict from the live state (#11), by
  `Get-SPSLifecycleActVerdict` (it reads and changes nothing). The new adapters only read: `Get-SPSLifecycleLiveSite` (the site by its
  address, with whether it has a hold) and `Get-SPSLifecycleGroupState` (`None`, `Active`, `SoftDeleted` or `NotFound`, by the ID as a
  GUID). A site that is gone is `SKIP-NOT-FOUND`, an address that now belongs to another site is `SKIP-SITEID-MISMATCH`, and a site
  that the engine would let through is kept back as `REVIEW-CONTENT-MODIFIED` (changed after the report, or no date) or
  `REVIEW-RETENTION` (a hold, or no hold flag at all: only a flag that says `False` lets a row through). The decision of the
  person is the action of the engine and never lifts a gate. The group is read only
  when the site has one and every gate before it has been passed. A read that fails is an error, never a verdict, so that it can never
  lead to an action, and only the messages that the tenant gives for a thing that does not exist are read as "not there". The lab
  has not checked these messages, nor `HasHolds`, nor the effect of a lock on the content date (#15).
- Act: the loop that applies the decisions, behind the safeguards (#12), as the public function `Invoke-SPSLifecycleAct` (the entry
  script does not call it yet). Report only is the default (`Act.Execute` must be exactly `$true`): every row is read again and gets
  the verdict it would get, and no adapter that changes the tenant is called. With `Execute`, a banner (the file, its date and age,
  the decisions, the most that the run will do), then the name of the tenant and a phrase that carries the number of actions
  (`DELETE n`, `ARCHIVE n` or `APPLY n`) are typed, and the tool stops when the input is redirected. `MaxActions` counts the actions
  that were tried, `DelaySeconds` is the pause between two actions, the run stops after 3 errors in a row, and each row is read
  again right before its action. The Act report `act-<time>.csv` has a row for each decision, written to the disk as it is made, and
  a row `InProgress` that is written before the tenant is touched for a decision (the tool does not act when it cannot be written): a
  run that is killed, or a window that is closed, during an action leaves it with no outcome after it, which says which site to look
  at, and an interrupted run (Ctrl+C) adds a row `Interrupted`.
  The actions follow the lab (27 and 28 October): a read-only site is unlocked, deleted into the recycle bin and locked again when
  that fails; a site with a group is deleted through its group; a lock writes its date in the lock journal; an archive can unlock
  the site first and lock it again afterwards, and add the administrator who signed in. A site that was unlocked is read again, and
  nothing is done if it changed meanwhile (the site ID, a hold, the content, the size of a deletion, its group and the home site,
  read again, and then the site one last time right before the write); a lock is said to be put back only when the site reports it, an address that another site took is left alone, a request
  to unlock that throws is treated as possibly applied, and an interrupted run puts the lock back too, with the same care. The home
  site is read for each row. Execute
  needs Microsoft 365 Archive to be on for sure before an archive. Every adapter that changes the tenant checks its target again (the
  tenant of the session, the host of the address, no OneDrive, no root site, no encoded slash, a group by its ID), and a structure test
  checks that each one does. None of these calls has run against a tenant yet.
- Act: `src/SPSSiteLifecycle.ps1 -Phase Act` runs the Act phase (#13), through `Invoke-SPSLifecycleAct`, with the same settings file and
  no other parameter. It shows the banner and the summary as information, and its exit code is `0` when the run ended as planned,
  `1` on any error (with a message that sends the person to the Act report), and `2` when the run ended but a row failed or could
  not be read, or when it stopped after 3 errors in a row, with a warning that names the report, so that a scheduler can tell it from
  a run that ended as planned. The Getting Started page says what a person does between the phases (filter the report, fill in
  `Decision`, save it as CSV) and how to run the Act: report only first, then one action with `MaxActions = 1`.
